Chapter 05

⚙️ 開発・実装(TDD)

設計を、テストを安全網にしながらコードへ落とす。TDDを土台に、フロント・バック・セキュアコーディングを一貫した規律で実装する。

TDD — Red / Green / Refactor

テストを先に書き（Red）、最小実装で通し（Green）、整える（Refactor）。テストなしの実装コミットを作らない。AIに実装させる場合も、先にテスト（仕様）を固めると生成の正しさを機械的に判定できる。

バグ修正は「再現テストを先に書く」ことから始める。再現できないバグは直したと言えない。修正後にそのテストが緑になることで「直った」を証明する。当てずっぽうの修正をしない。

コーディングの規律

  • 1コミット=1論理変更。テストと実装は同じコミットに含める。
  • 秘密情報・接続文字列のハードコード禁止。必ず環境変数経由。
  • リンタ・フォーマッタ・型チェックをCIとローカルの両方で同じコマンドで実行できるようにする。
  • モックは外部境界（HTTP / DB / 時刻 / 乱数）のみ。内部ロジックをモックしない。
  • ローカルのミドルウェアは Docker Compose（compose.yaml）で起動。アプリ本体はホストで動かす（ホットリロード優先）。

ディレクトリ構成（実装とテスト）

設計のレイヤー（03 設計）をそのままディレクトリに写す。ドメイン層は外部依存を持たない純粋なコードに保つ。テストは tests/ にピラミッド（単体→統合→E2E）で分ける。

実行系は package.json の scripts に集約し、ローカルとCIで同じコマンドを叩けるようにする。

フロントエンド実装

コンポーネント設計

表示(presentational)とロジック(hooks)を分離。状態は最小・近接配置。

型安全をAPI境界まで

OpenAPI / tRPC / zod でサーバ⇄クライアントの型を一致。APIの変更がコンパイルエラーで伝わる状態に。

4つの画面状態

ローディング / エラー / 空 / 権限なし を全画面で実装。AI生成はハッピーパスに偏る。

a11y

セマンティックHTML・キーボード操作・コントラストAA・alt/label。

Core Web Vitals

指標意味目標(良好)
LCP最大要素の表示時間≤ 2.5s
INP操作への応答性≤ 200ms
CLSレイアウトのずれ≤ 0.1

手段: 画像最適化（サイズ指定・遅延読込）、コード分割、不要JSの削減、レンダリング戦略（SSR/SSG/ISR/PPR）の使い分け。

バックエンド実装

  • 入力バリデーションを境界で必須化（zod / pydantic）。型と実行時検証を一致させ、信頼できない入力を内部へ通さない。
  • 冪等性・タイムアウト・リトライ・サーキットブレーカ — 特に決済や外部API連携。
  • N+1回避、トランザクション境界の明確化、インデックス活用（EXPLAINで確認）。
  • エラーを握りつぶさない。構造化ログ + 相関ID(trace id)で全リクエストを追跡可能に（08 運用・監視・保守）。
落とし穴: 論理削除テーブルは全クエリに WHERE deleted_at IS NULL。AIは集計・JOIN・ユニークチェックで削除済み行を巻き込みやすい。生成コードには N+1 / トランザクション漏れ / 削除済み行の巻き込みが混入しやすく、レビューで定型チェックする。

セキュアコーディング

実装時に最も混入しやすい脆弱性を、書く段階で潰す（横断の全体像は 09 セキュリティ）。

  • SQLは文字列連結せずプレースホルダ/ORM。出力は必ずエスケープ（XSS対策、dangerouslySetInnerHTMLを避ける）。
  • 認可はリソースごとに所有者チェック（IDOR対策）。「ログイン済み＝全権限」にしない。
  • 秘密は環境変数経由。LLMの出力をそのまま実行・DB書き込み・外部送信しない。

完了条件（チェックリスト）

  • 対象機能にテストがあり全件グリーン（TDDで実装）
  • lint / format / 型チェックが通る
  • 秘密情報のハードコードがない
  • （UI）4状態とa11yを満たす / （API）境界バリデーションがある
  • docker compose up -d から開発開始までの手順が README にある / STATUS.md 更新済み
AI活用: 先にテスト（仕様）を固めてから実装をAIに任せると、生成の正しさをテストで機械判定できる。ただし「テストを通して」と頼むと実装でなくテストを緩める挙動が出るため、緑になった理由を必ず確認する（06 テスト・レビュー・QA）。
