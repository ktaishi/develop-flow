AIと進める開発の路線図

準備から運用まで、8つの駅を順にたどります。各駅には、手を動かすための「手順」と、判断の拠り所になる「本（ハンドブック）」を並べました。

  1. 準備ツールを入れて最初の1タスクを通す手順セットアップ本全体原則
  2. ルール整備AIに毎回読ませる約束事を置く手順ルール / Skills本AIとの協働の実務
  3. 要件何を作るかを検証できる形にする手順全体像（Phase 地図）本要件定義
  4. 設計Plan を立て、決定を ADR に残す手順Plan・設計本設計本技術選定・インフラ
  5. 実装小さく作り、テストで囲む手順実装本開発・実装（TDD）
  6. 検証機械と人の目でレビューする手順PR・提出本テスト・レビュー・QA
  7. リリースCI/CD で安全に届ける手順CI/CD本デプロイ・リリース
  8. 運用エージェントを回し続け、学びを戻す手順エージェント運用本運用・監視・保守本セキュリティ

「手順」は Cursor / Claude Code / Codex での具体的な進め方、「本」はツールが変わっても残る考え方です。途中の駅から読み始めてもかまいません。

2026年11月の更新 GPT-4o / GPT-4.1 系の API 提供終了（2027-01-14）に合わせて既定モデルを見直し、Claude Code・Codex・Cursor の直近の変更と仕様駆動開発の広がりを整理しました。 変更点を読む

    ガイドまとめ

    人が読んで進めるチェックリストです。各項目から手順ガイドへ飛べます。AI に貼る指示文ではありません。

    ガイドまとめの出力

    AI セットアップ指示

    Cursor / Claude 等のチャットに貼る別ファイルです。上のガイドまとめとは用途が違い、リポ内にルール · tasks/ 等を作らせるための長文指示です。

    セットアップ指示のプレビュー
    チャットに貼ったあとに起きること
    1. 対象リポを IDE で開く（Cursor 推奨）。新規なら空ディレクトリで OK。
    2. AI チャットを新規スレッドで開き、コピーした指示をそのまま貼り付けて送信。
    3. AI が指示に従い、リポ内にファイルを作成・追記（ルール · tasks/ · ONBOARDING.md 等）。
    4. AI から完了報告（作成/変更ファイル一覧 · 検証結果 · 要確認操作）が返る。
    5. あなたが diff を確認 → 問題なければ git commit（AI は commit / push しない）。

    既存のルール・設定への影響

    状況起きること
    新規リポ サンプルルール · Plan テンプレを新規配置。上書きの心配なし。
    既存リポ · 同パスにファイルあり 指示どおり上書きせず、差分提示 · 追記 · 統合案。確認待ちになる場合あり。
    既存 .cursor/rules/ 等 足りないルールを追加。既存ファイルの削除 · 一括置換はしない。
    進行中の tasks/todo.md テンプレ全置換はしない。不足見出しの追記のみ。
    触らないもの アプリコード · .env 等 · git 履歴 · リモート / クラウド設定。

    既存ルールが充実しているリポでは、実行前にプレビューで追加されるファイル名を確認するのが安全です。
