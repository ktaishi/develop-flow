選び方のデフォルト

迷ったら次の使い分けから始める。1本に絞るなら、エディタ中心の人は Cursor、ターミナル中心の人は Claude Code。

  1. 日常のコーディング・小さい修正 → Cursor（Tab + Agent）。編集→確認のループが最速
  2. 調査・リファクタ・複数ファイルにまたがる作業の委譲 → Claude Code。Plan を立てさせて承認→実行
  3. 並列で複数タスクを投げて後で PR を回収 → Codex クラウド。レビューは人間が必ず行う
  4. CI・定期実行への組み込み → claude -p または codex exec（システム組み込み参照）

2本併用が現実解

多くのチームは「IDE 1本（Cursor）+ エージェント 1本（Claude Code または Codex）」で運用している。ルールは AGENTS.md を正本にして CLAUDE.md からシンボリックリンク（または冒頭で参照）し、二重管理を避ける。

Claude Code

ターミナルで動くコーディングエージェント。ファイル編集・コマンド実行・Git 操作までを一気通貫で任せられる。

最短セットアップ

# インストール（npm 経由）
npm install -g @anthropic-ai/claude-code

# リポジトリで起動
cd your-project
claude

# 初回に /init で CLAUDE.md の雛形を生成
> /init

押さえる機能 6つ

機能何ができるか使いどころ
CLAUDE.mdセッション開始時に必ず読まれる指示書規約・ビルドコマンド・禁止事項。短く保つ
Plan モード編集せず計画だけ提示、承認後に実行大きい変更の前。Shift+Tab で切替
Skills.claude/skills/<name>/SKILL.md。必要時だけ読まれる長手順リリース手順・調査手順など反復作業
Hooksツール実行前後にコマンドを強制実行編集後 lint、危険コマンドのブロック
サブエージェント調査などを別コンテキストに委譲大規模探索でメイン文脈を汚さない
MCP外部ツール（DB・ブラウザ・社内 API）接続claude mcp add で登録

運用のコツ

  • Explore → Plan → Code → Commit の順を守らせる。いきなり書かせると手戻りが増える
  • 許可プロンプトが多い場合は .claude/settings.json の permissions.allow に読み取り系コマンドを足す
  • 長セッションで迷走したら /clear で文脈を切る。直前の要約を貼り直す方が速い
  • CI への組み込みは claude -p "プロンプト"（ヘッドレス）。システム組み込みに例

Codex

OpenAI のコーディングエージェント。ローカル CLI とクラウド実行（Web から並列にタスクを投げ、PR で回収）の2形態が柱。

最短セットアップ

# インストール
npm install -g @openai/codex

# リポジトリで起動（ChatGPT アカウントでサインイン）
cd your-project
codex

# 非対話実行（CI・スクリプト向け）
codex exec "failing test を修正して"

押さえる機能 5つ

機能何ができるか使いどころ
AGENTS.md作業ディレクトリに近いものが優先される指示書モノレポはサブディレクトリにも置く
承認モードRead Only / Auto / Full Access初手は Auto。サンドボックス外は確認させる
クラウド実行Web からタスクを並列投入、結果は PR独立した小タスクの一括処理
config.tomlモデル・サンドボックス等の設定（~/.codex/）プロジェクト上書きは trusted のみ
コードレビューGitHub 連携で PR を自動レビュー人間レビューの前段に置く

運用のコツ

  • クラウド実行はタスクを小さく独立に切るほど成功率が上がる。「テスト追加」「型エラー解消」など1PR=1目的
  • 環境構築スクリプト（setup script）を整備すると、クラウド側でテストが回り精度が上がる
  • 並列で出た PR はまとめて人間がレビュー。PR・提出のチェックリストを適用

Cursor

VS Code をベースにした AI ネイティブ IDE。補完（Tab）・チャット・エージェントがエディタに統合されている。

押さえる機能 5つ

機能何ができるか使いどころ
Tabマルチ行・編集予測つきの補完常時。最も使用頻度が高い
Agent複数ファイル編集・コマンド実行機能追加・リファクタの主力
Plan モード実装前にタスク分解と計画を作る中規模以上の変更（Rules/Skills/Plan）
Rules（.mdc）alwaysApply / globs / description で適用条件を制御規約は alwaysApply、領域別は globs
Background Agentリモート環境で非同期実行長時間タスクの並列化

運用のコツ

  • Rules は1ファイル1関心事で分割し、alwaysApply: true は本当に毎回必要なものだけに絞る（コンテキスト節約）
  • 大きい変更は Plan モードで計画を確認してから実行。計画の修正はコードの修正より安い
  • 差分は必ずレビューしてから受け入れる。「全部 Accept」を習慣にしない

組み合わせ運用パターン

パターン構成向くチーム
IDE 主体Cursor で開発、複雑な委譲だけ Claude Codeフロントエンド中心・対話的に進めたい
エージェント主体Claude Code で開発、エディタは任意バックエンド・インフラ・CLI に慣れたチーム
並列回収型日中は Cursor / Claude Code、定型タスクは Codex クラウドへ一括投入小タスクが溜まりやすいチーム
レビュー強化型開発は任意 + PR レビューを Codex / CI の AI レビューで前段化レビュアー不足のチーム

Gotchas（共通の落とし穴）

  • ルールファイルの肥大化はすべてのツールで性能を下げる。毎回必要な指示だけ常駐させ、長い手順は Skills / description 起動に逃がす
  • ツールごとにルールを別管理すると必ず乖離する。正本を1つ決めて他は参照にする
  • 「動いた」と「正しい」は別。エージェントの自己申告を信じず、テスト・lint・実行確認で検証する（運用）
  • 料金・モデル・機能名は変化が速い。最新は各公式 changelog を確認し、本ページは「型」として読む
