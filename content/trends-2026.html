2026-11-13 時点

2026年11月のトレンドと、このガイドでの扱い

この半年で変わったのは、モデルの世代、エージェントの動かし方、そして「仕様とルールを先に置く」進め方の3つである。ここでは事実関係を出典つきで整理し、ガイドのどのページに反映したかを示す。

読み方: 変化の速い領域なので、日付と出典を必ず確認すること。「二次情報」と書いた項目は公式ページを直接確認できていない。移行作業の前に、末尾の公式リンクで最新の内容を確かめてほしい。

1. モデルの世代交代 — GPT-4o 系は 2027-01-14 に API 終了

OpenAI は 2026-10-14 に、GPT-4o・GPT-4o mini・GPT-4.1・GPT-4.1 mini を 2027-01-14 に API から削除すると通知した。推奨される移行先はいずれも gpt-6-luna である。o4-mini は 2026-10-23 に停止済みで、移行先は gpt-5.6-terra とされている。

モデル ID位置づけこのサイトでの扱い
gpt-6-luna低コスト・大量処理向け。GPT-4o 系の公式な移行先「設定」の既定モデル
gpt-6.1-terra / gpt-6.1-sol中位 / 本番・コーディング向けの標準（二次情報）選択可
gpt-6-astra最上位。難度の高いエージェント作業向け（二次情報）選択可

gpt-4o / gpt-4o-mini / gpt-4.1 / gpt-4.1-mini2027-01-14 に API 終了一覧から削除。保存済みの設定は gpt-6-luna に読み替え

自分のプロダクトでやること: コード・設定・プロンプト管理ツールを gpt-4o、gpt-4.1、o4-mini で検索し、モデル ID を1か所の設定に寄せる。移行は ID の置換だけで終わらせず、実データでの回帰確認を挟む。二次情報では、GPT-6 上位モデルのツール呼び出しは Responses API が前提とされているため、Chat Completions でツールを使っている箇所は先に洗い出しておく。

2. Claude Code — 権限まわりが「確認できないものは止める」方向へ

  • 既定モデルが Claude Fable 5.2 に（2.1.321）。Opus 4.8 の fast mode は 2026-11-30 に削除され、以後はエラーになる。速度が必要なら Opus 5.5 へ移る。
  • auto mode の分類器フォールバック廃止（2.1.319）。テレメトリや機能フラグを切った環境、LLM ゲートウェイ越しの環境では、サーバー側で確認できない呼び出しは「確認を求める」か「拒否」になる。permissions.denyInsteadOfPrompting で、止まったままの確認を拒否に置き換えられる。
  • 作業ディレクトリ外への書き込みを止める設定 permissions.blockWritesOutsideWorkingDirectories が追加された（2.1.314）。
  • サブエージェントの effort を個別に指定できる CLAUDE_CODE_SUBAGENT_EFFORT が追加され、ultrathink はそのターンを xhigh で実行するようになった（2.1.311〜2.1.316）。
  • MCP タスクがターミナルでバックグラウンド実行され、完了時に結果が報告される（2.1.319）。
  • 巨大な CLAUDE.md やルールファイルを冒頭だけ読んで上書きしてしまう不具合が修正された（2.1.312）。ルールファイルを肥大化させない運用の裏づけにもなる。

反映先: Claude Code 設定早見、エージェント運用、セキュリティ（横断）。

3. Codex — 複数エージェントを束ねる画面が CLI に

  • CLI 0.167.0（2026-11-06）で、codex agents --no-daemon から開く「エージェント コマンドセンター」が入り、未読の結果が印で分かるようになった。接続先バックエンドの切り替えも下書きを保ったまま行える。
  • 承認プロンプトを開いたまま、パッチの中身をその場で確認できる。
  • 既定のカタログモデルは GPT-6.1 Sol（0.161.0）。
  • Codex デスクトップアプリは 2026-07-09 に ChatGPT デスクトップアプリへ統合された。ワークフローや MCP 設定をまとめて配布するプラグインの仕組みは 2026年3月から提供されている。

反映先: Codex 設定早見、ハーネスとマルチエージェント。

4. Cursor — エディタの外へ広がる

  • SpaceX による Cursor（Anysphere）の買収が 2026-08-14 に完了した。契約・データ取り扱いの確認先が変わっていないか、社内の利用規程を見直す機会になる。
  • Voice Chat with Agents（2026-11-06）: エージェントと音声で双方向に会話できる。従来の音声入力（ディクテーション）とは別機能。
  • Build Live Apps（2026-11-05）: データベースと認証つきのアプリを Cursor 上で作成・デプロイし、チームに共有できる。
  • Auto モードは、リクエストごとにモデルを振り分ける Cursor Router が担う（2026-07-22）。iOS アプリとローカルエージェントの Remote Control、Agent SDK も提供されている。

反映先: Cursor 設定早見、ツール徹底比較。

5. 進め方のトレンド — 仕様とルールを先に置く

仕様駆動開発（SDD）

意図 → 仕様 → 実装計画 → タスク分解の順に進め、コードはその後に書かせる。GitHub Spec Kit は spec.md / plan.md / tasks.md の3点で形式化した。本ガイドの Phase 2「Plan」と同じ考え方である。

AGENTS.md と SKILL.md の定着

リポジトリ調査では、エージェント向けコンテキストファイルのうち AGENTS.md が標準として広がっている。Skills は多くのリポジトリで1〜2個しか定義されておらず、数より質が効く。

単体から複数エージェントへ

Anthropic のレポートは、単一エージェントから協調するチームへの移行と、数時間〜数日単位の長時間タスクを主要な変化に挙げる。並列化するほど、タスク分解と検証の設計が成果を左右する。

人の監督は減らない

同レポートの紹介記事によれば、開発者は仕事の約60%で AI を使う一方、完全に任せているのは 0〜20% にとどまる。「レビュー前提の協働者」という本ガイドの原則は変わらない。

反映先: Plan・設計、Rules / Skills / Plan の切り分け、Skills：判断と更新、全体原則。
